# 新增交易：勾選式成交與計畫登錄

日期：2026-08-28。部署範圍：既有本機開發站 `http://127.0.0.1:3000/`，未部署雲端。

## 操作入口

1. 首頁「新增交易」進入工作區登錄頁；寬螢幕雙欄、窄螢幕上下排列，沿用既有樣式。
2. 填入已發生的成交：帳戶、市場、標的、方向、時間、股數、成交價、費用。
3. 確認引擎判定的新建倉／加碼／減碼／平倉／反手及前後股數。
4. 勾選型態、量價、加碼理由、策略條件、停利停損依據；輸入停利停損價格。
5. 提交後一次寫入成交、計畫歷史、固定策略引用及 `entryContexts`，清除草稿。關閉或返回總覽只保留草稿，不產生成交。
6. 在持倉 K 線／閉環詳情的「成交登錄證據」及重播時間軸查看原始證據。交易行為分析可依進場型態、量價及已登錄的加碼紀錄篩選。

## 計算與證據

- 使用原 FIFO 引擎依成交時間分類，同時間的新成交排在已有成交後，明示日線無法確認盤中先後。
- 反手只把新進場證據連到 `cycle-{fillId}-open`，舊閉環評分、計畫與策略保持不變。
- 加碼沿用原固定策略版本；本次條件確認独立保存，不重設原開倉檢查。未改價格不追加計畫版本。
- 10 根 K 線嚴格早於成交所在市場日期；第 11 根用作量比基準。成交日 K 線另列「事後資訊」。缺成交量不補零。
- 主要資產影響是「目標價相對參考現價的整筆部位變化 ÷ 登錄後帳號淨值」，以同份 USD／匯率快照估算。成本盈虧另列，不混作已實現損益。
- 範例測試：20 股、均價 100、現價 120、停損 110，成本盈虧 +USD 200，但資產情境變化 −USD 200。
- 歷史補登無當時估值快照時不計算曝險；缺有效淨值、報價或匯率時說明原因，不以成本或零補值。
- 全部勾選確認、策略指派及新增計畫保留實際登錄時間，標示事後資料；不生成完美／錯誤等品質結論。
- 歷史插單若會移動已有策略、計畫、評分或登錄證據的閉環，阻擋並列出受影響識別碼。

## 保存

- `entryDraft` 與 `entryContexts` 在同一帳號 Dataset JSON 內；無新增資料表。
- 自動保存、首頁手動保存、JSON 匯出／匯入沿用完整快照機制，包含行情證據、規則檢查與估值快照。
- 已驗證草稿不影響成交／現金／庫存、提交清草稿、重啟讀回、並行版本衝突不覆蓋。
- 行情與報價請求平行啟動，切換標的取消舊請求；回應不覆寫新標的，逾時仍可登錄真實成交。已保存的登錄證據不隨背景報價更新。

## 驗證紀錄

- 全套 Node 自動測試：227 項通過。
- TypeScript 檢查、相關檔案 ESLint、正式建置通過。
- 實際 TSX 事件／Hook 測試：首頁進入登錄、草稿自動保存、操作確認、提交及重新讀回。
- 介面 SSR 測試：單選／多選、加碼沿用、平倉隱藏進場條件、無策略保存、無效停損仍可修正。
- Canvas 測試：300／1000px 寬度下十根 K 線、成交量、成交標記、停利停損線及逐日滑桿。
- 分析測試：總累計、年、月、週與策略版本／登錄標籤篩選，同步影響品質、矩陣、盈虧結構與規則稽核；一個閉環不因多次操作重複計數。
- 隔離 HTTP 儲存測試：3.2MB 完整快照、版本衝突、服務重啟及歷史備份通過。登錄新增欄位另以臨時資料夾完整存取測試驗證。
- 本機首頁 HTTP 200。依既有工作規範未操作真實帳號做瀏覽器點擊／截圖驗收；供使用者在既有站點驗收。
- 正式帳號沒有插入測試成交：核對 554 筆成交、64 筆資金活動與帳戶資料，與原始來源備份一致。

## 第一版限制

- 量價觀察是人工標記；日成交量不能代表法人買賣或大戶持股。
- 歷史曝險缺快照時保持不可計算，不重建假快照。
- 已保存的加碼證據篩選不推測舊交易；未登錄不代表沒有加碼。
- 行情是否可取得依既有行情服務而定；缺資料不妨礙保存真實成交。
