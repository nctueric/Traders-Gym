- 設定 Sites `GOOGLE_CLIENT_ID`。現有環境為空；正式環境不能啟用 `LOCAL_ACCOUNT_SERVICE`。
- 確认試用使用本機或線上副本，或先完成逐筆差異核對。

## 已知限制

- 歷史列表從升級後第一次成功寫入開始建立；發布前獨立匯出仍是必要保險。
- 清理容量為快照資料量估計，不等於供應商帳單或整個 R2 bucket 的實際容量。失敗／競態寫入可能留下尚未被 D1 引用的 R2 物件；本版不掃描刪除這些物件，避免誤刪，需後續盤點。
- 初次取得 Google 擁有者前，不以測試身份或另一登入方案搶先綁定真實 primary。
- 七日實際試用、私人入口／Google 共存、跨裝置與真實第二身分仍須外部驗證。

## 資料復原步驟

1. 發現異常先停止所有裝置編輯並關閉工作台；保留出錯畫面的 JSON 副本，記錄版本、時間及錯誤。必要時從管理後台強制登出測試成員。
2. 在管理後台下載目前版與候選歷史版，核對來源、筆數、SHA-256 與已知計算案例。不要直接刪除 D1 或 R2。
3. 使用歷史還原，先讀取目前版本再確認。其他頁籤期間若有修改，版本衝突會中止；先保留兩邊副本再處理。
4. 沒有合適歷史版時，用獨立 JSON 備份匯入並儲存為新版本；保留原始檔。只有經確認的來源才可覆蓋目前工作帳本。
5. 重新登入，匯出核對完整 JSON、成交／資金／行情／復盤筆數及持倉計算結果，再恢復寫入。
6. 程式發布失敗時檢查已套用遷移；不得直接回退到沒有帳號隔離的第 24 版 API。優先修復目前安全後端，保留資料與歷史。
