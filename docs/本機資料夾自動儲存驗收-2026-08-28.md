# 本機資料夾自動儲存修復｜2026-08-28

## 決策

依使用者指示，把本機帳號主要儲存改至專案上層 `自動儲存/`，保留原 D1 與下載備份。Vite 本機 middleware 處理 `/api/trade-records`；正式雲端路由仍保留 D1 實作，但本輪沒有部署。

## 原有問題與修復

舊前端的本機暫存排除了 `marketBars`，但 PUT 卻送出完整 Dataset。實際下載備份 compact JSON 為 3,282,806 bytes，超過 [D1 每列 2,000,000 bytes 限制](https://developers.cloudflare.com/d1/platform/limits/)。服務記錄有持續 HTTP 500，帳號版本停在 1。

本次改為共用 durable Dataset：只排除可重新下載的行情及檔案 `_storage` metadata，保留所有人工欄位。前端、帳號切換及後端一致使用此口徑。1.8 MB UTF-8 帳本大小檢查保留餘量；不只計算字串字數。

其他修復：

- 背景 Worker 出錯或 5 秒無回應時回退序列化，避免永遠不儲存。
- 自動儲存只依帳本變動排程，不被連續行情更新重設。
- 單帳號寫入排隊、20 秒請求逾時、5～30 秒重試及上線重試。
- 暫存失敗不阻斷資料庫／檔案保存，也不宣稱暫存一定安全。
- 成功回應即使遇到後续編輯仍確認版本，防止使用舊版本繼續寫入。
- 多頁籤有真正衝突時停止覆寫；不提前提升版本再盲目重送。
- 待保存日誌保留 baseline。重啟只有在 baseline 相同時恢復，舊版無 baseline 暫存另存恢復副本，不猜测新舊。
- 離頁前保存待處理日誌，未同步時使用瀏覽器原生離頁提醒。
- D1 保留路由亦改成同一 SQL 內比較版本再寫入，避免先 SELECT 後寫入的競態。

## 本機檔案安全

帳號分檔、識別碼驗證、同來源／本機 Host 檢查、跨網站寫入拒絕、檔案 lock、版本比對、SHA-256、先保留歷史版本再同步寫入暫存檔並 rename。檔案損壞或鎖定時不自動回滾／覆蓋。主檔與歷史檔可直接經網站 JSON 匯入。
