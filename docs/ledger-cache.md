# 帳本本機快取與背景同步

## 決策

正式資料仍以 Cloudflare D1 的版本與私人 R2 完整快照為準。登入後，瀏覽器以 IndexedDB 保存每位使用者、每份帳本各自隔離的完整快取；畫面修改先進入 React 狀態與裝置快取，再由既有的序列化儲存佇列背景同步雲端。

啟動流程：`D1 首頁摘要與版本 → 比對 IndexedDB → 相同版本直接開啟 → 背景查詢雲端版本`。快取缺少、格式損壞或版本不同時，回到既有的 R2 完整下載與校驗流程，不把舊資料當成最新資料。

寫入流程：`畫面立即更新 → 150ms 合併寫入裝置快取（標記待同步及雲端基線）→ 1 秒停止輸入後背景 PUT → Cloudflare CAS 成功 → 快取更新為已同步版本`。多頁籤或多裝置競爭仍交由既有版本衝突與三方合併處理。

## 方案比較

| 方案 | 速度 | 一致性與隱私 | 決策 |
| --- | --- | --- | --- |
| Cloudflare CDN 快取完整帳本 | 跨裝置讀取快 | 私人回應容易誤設共享快取，失效與權限較複雜 | 不採用 |
| 只保留 D1 首頁摘要 | 首屏快，但進完整工作區仍需下載 R2 | 安全且簡單 | 保留，作為版本戳記與降級畫面 |
| Service Worker Cache Storage | 可離線 | 私人 API 回應與認證快取規則較難維護 | 不採用 |
| IndexedDB＋背景再驗證 | 同裝置再次開啟最快，可保存待同步修改 | 需版本校驗與登出清除 | 採用 |

## 安全與失敗處理

- 快取鍵包含使用者 ID 與帳本 ID；內容、雲端基線及版本格式都需驗證。
- 普通過期快取會移除；未確認同步的修改不會因版本改變而直接刪除。
- 本機寫入依序執行，避免較舊的「待同步」狀態覆蓋較新的「雲端已確認」狀態。
- IndexedDB 不可用或額度不足時靜默退回原有雲端流程，不阻止使用者交易紀錄。
- 登出會清除目前使用者的本機帳本快取；訪客資料仍只存在當頁記憶體。

若未來帳本超過瀏覽器儲存額度，應改成分片事件日誌與最近讀取區塊，而不是放寬共享 HTTP 快取。
